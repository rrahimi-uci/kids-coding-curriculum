The big idea: inheritance

A child class gets everything from its parent class for free. Then it changes only what is different. Write the parent in brackets:

A child class

class Sprinter(Enemy):                  # a Sprinter IS AN Enemy
    def __init__(self, name, x=0, y=0, speed=3):
        super().__init__(name, x, y)    # parent sets name, x, y
        self.speed = speed              # then the extra attribute

    def move(self):                     # override the parent's move
        self.x = self.x + self.speed
        self.steps = self.steps + 1

Tipsuper() = “do the parent’s part”

super().__init__(name, x, y) runs the parent’s setup. super().move() runs the parent’s move, so the child can add something on top. If a child has its own __init__ and forgets super().__init__, its parent’s attributes are missing and you get an AttributeError.

Polymorphism: one call, many behaviors

enemies = [Enemy("Blob"), Guard("Rocky"), Sprinter("Zoom")]
for enemy in enemies:
    enemy.move()        # each one moves its OWN way

The loop does not need to know what kind each enemy is. Polymorphism means “many shapes”: the same message, move(), gives different results.

Composition: “has a”

Not everything is a family. A Game is not a kind of Player, but a Game has Players. When an object keeps other objects in an attribute (often a list), that is composition.

Is a inheritance Has a composition
A Sprinter is an Enemy. A Game has Players.
A Star is a Shape. A Party has Heroes.
class Star(Shape): self.players = []
