Two ways to search

Linear search looks at the items one by one, from the start. It works on any list, but a long list means a long search.

Binary search only works on a sorted list. It looks at the middle item. If that is too small, the answer must be on the right, so it throws away the whole left half (and the other way round). Every step cuts the list in half.

Gray boxes have been thrown away; the thick orange box is the one we look at (mid). Searching for 44 took 3 steps. Linear search would take 7.

How fast is fast?

To compare algorithms, count the steps in the worst case (the unluckiest search).

Items in the list Linear search Binary search
10 10 steps 4 steps
100 100 steps 7 steps
1000 1000 steps 10 steps

When the list gets 10 times bigger, linear search does 10 times more work. Binary search only does about 3 more steps!

Binary search in Python

low = 0
high = len(items) - 1          # the LAST index, not the length
while low <= high:             # <= : one item left is still worth checking
    mid = (low + high) // 2    # // makes a whole number
    if items[mid] == target:
        return mid
    elif items[mid] < target:
        low = mid + 1          # throw away the left half (and mid)
    else:
        high = mid - 1         # throw away the right half (and mid)
return -1                      # nothing left: not in the list

TipFilter bubbles

Search engines are amazingly fast, but they also choose which results to show you first, based on what you clicked before. If you only ever see what you already like, you are in a “filter bubble”. Try different search words, look at more than one source, and ask a grown-up when something seems odd.
