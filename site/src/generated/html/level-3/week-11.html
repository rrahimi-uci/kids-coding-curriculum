Tests: crash-test dummies for your code

A test is a tiny program that checks your program. Test the logic (moving, scoring, saving), not the drawing. Test normal cases and edge cases: the corner, the wall, the empty list, the last life.

Example: tests for a tiny Player

muncher\_demo.py

class Player:
    def __init__(self, row, col):
        self.row = row
        self.col = col
        self.score = 0

    def move(self, grid, d_row, d_col):
        new_row, new_col = self.row + d_row, self.col + d_col
        if grid[new_row][new_col] == "#":
            return False
        self.row, self.col = new_row, new_col
        if grid[new_row][new_col] == "*":
            self.score += 10
            grid[new_row][new_col] = "."
        return True

test\_muncher\_demo.py

from muncher_demo import Player

def make_grid():   # a tiny maze: wall, empty, star, empty, wall
    return [list("#####"), list("#.*.#"), list("#####")]

def test_player_moves_into_an_empty_cell():
    p = Player(1, 1)
    assert p.move(make_grid(), 0, 1) is True
    assert (p.row, p.col) == (1, 2)

def test_walls_block_the_player():          # edge case
    p = Player(1, 1)
    assert p.move(make_grid(), -1, 0) is False
    assert (p.row, p.col) == (1, 1)

def test_eating_a_star_scores_10_once():    # edge case
    grid = make_grid()
    p = Player(1, 1)
    p.move(grid, 0, 1)
    p.move(grid, 0, -1)
    p.move(grid, 0, 1)
    assert p.score == 10

How to run your tests: in Thonny choose Tools → Open system shell..., make sure you are in your project folder, and type python -m pytest -q. Each dot is a passing test; an F is a failing one, with its name and the line that failed.

TipIs my test any good?

Break your code on purpose. Does the test go red? If not, the test is not checking anything. Then fix the code and watch it go green.
