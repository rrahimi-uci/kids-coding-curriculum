TipWhat is this?

For the next four weeks you will design and build a program that is bigger than anything you have made so far — and you will build it like real software makers do: plan first, save your progress with git, test it with pytest, ask people to try it, and explain your design. You can work alone or in a pair.

TipCommit like a pro

Commit every time something small works: "Add Hero class", "Stop hero walking through walls", "Test that treasure adds 1 point". Messages like "stuff" or "final" do not count as meaningful.

6. Testing your project

Test the logic, not the drawing. Keep rules (moving, scoring, saving, sorting, predicting) in classes and functions that do not use turtle, and keep the turtle code in its own part. Ideas:

  • a wall blocks a move; collecting treasure adds a point;

  • your search or sort gives the right answer on a tiny example and an edge case (empty list, unreachable square);

  • saving and loading gives back the same data (use pytest’s tmp_path folder);

  • your classifier predicts the right label for an obvious example.

test_my_project.py in the starter folder has examples. Run your tests from Thonny’s Tools → Open system shell… with python3 -m pytest -q.

9. Need more time, or want more?

Start from a starter template and keep it small: 2 classes, 3 features, 5 simple tests (one per method). Ask your teacher for a “feature card” with one small step at a time. It is fine to finish fewer features well. Add a second level or mode loaded from a file; write tests before the code (test-first); use BFS or recursion in a second place; add a settings dictionary saved as JSON; try k-nearest neighbors (3 vote) for option (c).
