The big idea

A class is a blueprint, like a cookie cutter. An object is a thing made from the blueprint, like one cookie. Every object made from the same class has the same kinds of facts, but its own values.

Anatomy of a class

Every part has a job

class Pet:                          # 1. the blueprint (capital P)
    def __init__(self, name):       # 2. setup: runs when a pet is made
        self.name = name            # 3. attributes: facts it remembers
        self.hunger = 5

    def feed(self):                 # 4. a method: an action
        self.hunger = self.hunger - 3   # MY hunger goes down

pip = Pet("Pip")                    # 5. make an object
pip.feed()                          # 6. ask it to do something
print(pip.hunger)                   #    prints 2

TipWhat is self?

self means “this object” or “my”. When you write pip.feed(), Python runs feed with self set to pip. So self.hunger is Pip’s hunger. Every method needs self as its first parameter, and every attribute is written self.something.

From dictionary to class

In Level 2 you might have written pip = {"name": "Pip", "hunger": 5}. A dictionary holds the facts. A class holds the facts and the actions, all in one place, so you can make 100 pets that all know how to feed().

TipKind design

Our pets never get sick, run away or say “you forgot me!”. Good games are fun because you want to play, not because they make you feel guilty. When you design a game, ask: “Is this fair and kind to the player?”
