The big idea: games wait for events

Most programs you wrote ran from top to bottom and stopped. A game waits. When something happens (a key press, a timer ringing), turtle calls one of your functions. The thing that happens is an event; the function that answers it is a handler.

Keys call handlers

def go_left():
    player.setx(player.xcor() - 20)

screen.onkey(go_left, "Left")   # when Left is pressed, call go_left
screen.listen()                 # switch on the "doorbell" for keys

Notice: go_left has no brackets in the onkey line. We hand turtle the function, and turtle calls it later. With brackets, Python would call it right away, only once.

The game loop

A game is like a flip book: every frame the world moves a tiny bit. Our game loop does one frame, then asks turtle to call it again soon.

One frame of Dodge the Meteors (shortened)

state = {"score": 0, "running": True}

def game_loop():
    for meteor in meteors:                      # a list of turtles
        meteor.sety(meteor.ycor() - 8)          # 1. move
        if is_touching(meteor.xcor(), meteor.ycor(),
                       player.xcor(), player.ycor(), 30):
            state["running"] = False            # 2. check: hit!
    if state["running"]:
        screen.ontimer(game_loop, 50)           # 4. again in 50 ms

Touching = close enough

Two things touch when the distance between them is small. math.dist measures the distance between two points: math.dist((0, 0), (30, 40)) gives 50.0. If that is less than about 30, the meteor hit the player.
