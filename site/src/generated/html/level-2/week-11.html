The big idea: test the brain, playtest the fun

Your program has two kinds of functions. Logic functions (the brain) take values in and give an answer back with return: pytest can check those automatically. Drawing functions (the paint) make pictures: a computer cannot tell whether your star looks nice, but a playtester can.

Two tricks make your functions easy to test:

  1. Put the start-up code (make the screen, start the loop) under if __name__ == "__main__":. Then pytest can borrow your functions without starting the game.

  2. Give file functions the file name as a parameter. Then the game and the tests can use different files, for example highscore.txt for playing and test_scores.txt for testing, and your tests never wipe your real high score.

Test a normal case (an everyday value) and edge cases (values at the very limit: the edge of the screen, a score of 0, a file that does not exist yet). Bugs love to hide at the edges.

Exercise11.2: Write three tests

Plan your tests first. Pick functions that return something.

Function Input Expected answer Normal or edge?
next_x 280, 1 280 (stays on screen) edge

Make a new file in the same folder as your game. Its name must start with test_, for example test_mygame.py. Each test is a function whose name starts with test_:

test\_mygame.py (part)

from mygame import load_high_score, next_x, save_high_score

def test_stops_at_the_right_edge():
    assert next_x(280, 1) == 280

def test_high_score_round_trip():
    save_high_score(42, "test_scores.txt")
    assert load_high_score("test_scores.txt") == 42

To run them: press F5 on your game once, close its window, then in Thonny choose Tools > Open system shell… and type (use python3 if python is not found):

python -m pytest test_mygame.py -v

PASSED means the function gave the expected answer. FAILED means it did not: read the line starting with E to see what came out instead. A test that fails is not a disaster, it is a bug you found before a player did!
