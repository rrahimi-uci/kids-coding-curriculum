The big idea: a function is a machine

A function is like a machine. Values go in through the parameters. The machine works on them. An answer comes back out with return.

A function with two parameters that returns an answer

def damage(attack, shield):
    """Return the damage a hit does."""
    return attack - shield

hit = damage(12, 5)       # 12 goes into attack, 5 goes into shield
print(f"Ouch! {hit} damage")

The values in the brackets when you call the function (12 and 5) are arguments. They fill the parameters (attack and shield) in the same order.

Print or return?

print(answer) return answer
Shows the answer on the screen. Hands the answer back to the code that called the function.
Like shouting it out of a window: you cannot keep it. Like putting it in your hand: you can store it or do math with it.
The function gives back None (nothing). The function gives back the answer.

Bug hunt clue: if you see the word None where a number should be, a function probably printed instead of returning.

Docstrings: notes for future-you

A docstring is a sentence in triple quotes just under the def line. It says what the function gives back. Thonny shows it when you hover over the function name, and your friends can read it to understand your code.

What happens in a function stays in a function

Variables you make inside a function (like result) only exist inside it. Outside the function, Python says NameError. If you need the value outside, return it.
